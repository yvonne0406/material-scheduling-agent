# 需求与成功标准

用户：内容运营人员。目标：对素材进行审核，形成无冲突且确认状态明确的排期草稿。只使用合成数据，不接入实际发布。

输出按素材包含：审核状态、风险原因、用户要求时间、建议时间、待确认事项、草稿保存状态和草稿 ID。任务状态与草稿保存状态分开，避免把建议误报为已保存。

## 验收矩阵（已实现，验证证据见03-evaluation.md）

| 场景 | 输入 | 必须验证 |
| --- | --- | --- |
| 正常 | examples/inputs/normal.json | 审核通过、无冲突、草稿真实落库 |
| 信息不足 | examples/inputs/missing-info.json | 指出缺失信息，不猜测，不保存可执行排期 |
| 规则风险 | examples/inputs/risk.json | 返回具体规则与风险，阻断不允许的排期 |
| 时段冲突 | examples/inputs/conflict.json | 查替代时段，保留硬性要求，建议需确认 |
| 重复提交 | examples/inputs/duplicate.json | 与正常输入连续执行，只产生一份草稿 |
| 保存失败 | examples/inputs/save-failure.json | 注入保存故障，明确失败，无伪造草稿 ID |

补充：达到工具次数上限时明确未完成；改变占用时段后模型行为随结果变化；至少两条真实模型路径；至少三组实际输出与 Trace。

范围外：UI、多 Agent、线上部署、真实媒体分析、真实发布。审核依据合成元数据和规则，不声称具备视频内容识别能力。
