# 复盘与改进

最难问题是把模型的灵活决策与确认、保存事实隔离：模型需要选择替代时间，但不能自行宣称用户同意或数据库保存成功。

实际改进：最初Mock通过后，真实模型把自身草稿的时段误判为冲突；查询排除当前请求预留后修复。随后发现幂等命中跳过了风险和时段复查，又补充复用前检查。最后新增独立用户确认事务，确认前重新加载资料并校验建议，保证仍是同一草稿。

真实模型文字曾出现未经工具支持的时间，保留失败Trace并把工具核验后的候选放入结构化结果；不能将自由文字当事实。持续失败与成功重试分别验证，避免把故障注入后的最终成功误记为失败。

工程学习：sqlite3连接上下文只管理事务，不自动关闭，Windows临时数据库测试暴露文件占用，改用显式关闭。测试必须涵盖失败、资料变化、重复操作及恶意模型参数，而不仅验证正常流程。

时间：候选人自报实际投入1.5小时，贡献为梳理搭建思路、明确方向与效果。代码、测试与后续交付整理主要由AI完成，详见04-ai-usage.md。

限制：当前是单账号、单时点合成排期，不处理视频持续时间与历史日期校验；支持确认同一草稿，但不支持任意编辑草稿版本；无多用户鉴权；未测试大规模并发；真实模型小样本结果不代表稳定通过率。

下一步优先做输入Schema、草稿版本编辑、明确的人工补料接口和更大样本评估，再考虑界面与部署。
