# 设计与技术取舍

Python 3.11 + CLI + SQLite，未采用第三方 Agent 框架。模型通过 HTTP 接收消息并返回 JSON 动作；执行器白名单分发工具，将真实工具结果追加到消息后再次请求模型，直到结束或达到上限。Mock 采用固定策略，和真实模式分别标记。

动作格式为 tool/arguments/reason，或 finish/reason；reason 是简短公开依据，不是内部思维链。每次运行记录 run_id、模型别名、模式、步骤、参数、结果和结束状态。Trace 位于 runner.py，存储逻辑与工具集中在 service.py。HTTP 超时45秒，无自动网络重试；模型可以根据业务工具错误选择重试。

默认上限8轮模型调用、12次工具调用，每轮最多一个工具。达到上限返回 limit_reached 并保留已保存结果；模型声称完成但没有成功保存证据时返回 incomplete。

工具包括素材读取、规则检查、时段查询、草稿保存。保存重新检查规则和时段，在 SQLite BEGIN IMMEDIATE 事务中写入草稿与时段预留。request_id 绑定规范化 JSON 请求指纹，同 ID 同内容复用草稿，不同内容拒绝。时间统一转UTC；查询不将当前请求自己的预留视为冲突。

确认来自原始输入，模型不能通过工具参数授予自己同意。修改原始要求的建议只能待确认；待确认不预留时段，已确认草稿预留时段。代码没有发布工具，所有结果 published=false。交互CLI收到用户输入CONFIRM后调用独立的confirm_draft，在同一事务内复核资料、原建议和时段，更新同一草稿并预留时段。重复确认幂等；该方法不在模型工具白名单中。

权衡：此规模不需要框架和Web界面；元数据审核可重复验证，但不能代表真实视频内容审核。单账号、单时点、整点候选不足以处理生产排期；配置和输入也未实现完整JSON Schema验证。用户输入是可信CLI输入边界，不是鉴权系统。

交互入口interactive.py可逐项收集请求或载入JSON，展示结构化结果，允许接受或拒绝替代建议。接受仅确认草稿，不执行发布。持久故障由显式test_mode和fail_always模拟，可验证工具持续失败不被当作成功。
